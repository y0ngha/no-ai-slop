# 여러 글 종류에서의 읽기 쉬움 검증

2026-10-07, 기술 설명·전문 보고서·일반 글·업무 문서·슬랙 요청을 영어와 한국어로 검증했다. 별도로 남겨 둔 두 혼합 사례까지 총 12편이다. 원문은 스킬과 이전 평가를 보지 않은 작성 에이전트가 만든 가상 문서이며, 실제 회사의 정책이나 실험 결과가 아니다.

사용자가 요청한 기준은 **평소 사용하는 어휘, 사람이 따라가기 쉬운 흐름, 과장되거나 내용 없는 표현을 덜어내는 것**이었다. 겉으로 전문적으로 보이거나 점수가 높다는 이유만으로 통과시키지 않았다.

## 평가 범위와 방식

- 첫 평가: 다섯 종류 × 두 언어의 10편을 현재 스킬로 편집한 뒤 세 모델이 각각 읽었다.
- 보완 평가: 수정한 네 편과 처음 평가에 넣지 않은 두 편을 세 모델이 새 문맥에서 읽었다.
- 마지막 확인: 중복 표현을 추가로 정리한 두 편을 세 모델이 다시 읽었다.
- 총 54건의 문서 평가와 108개의 이해 질문 답변을 받았다. 마지막에 원문과 최종본 12쌍을 독립적으로 대조해 의미 보존도 확인했다.

모델은 `gpt-6-luna`(처음 읽는 동료), `gpt-5.6-terra`(운영 책임자), `gpt-6.1-sol`(편집자)다. 공통 기준은 익숙한 어휘, 흐름, 의미의 명확성, 빈 수사·상투 표현의 부재, 글의 용도에 맞는지의 다섯 항목이다. 각 항목 10점이며 아래 총점은 **항목 합계 × 2**로 계산했다. 모델과 페르소나를 함께 바꿨으므로 모델 간 성능 비교로 해석할 수 없다.

평가자는 원문이나 스킬, 이전 점수와 다른 평가자의 답변을 보지 않았다. 보완 평가에는 편집자가 확인한 미결 질문을 함께 제공했지만, 질문을 표시했다고 내용이 해결된 것으로 보지 않도록 했다.

## 실제로 고친 부분

**업무 문서도 평소 쓰는 말로 쓴다.** 원문의 ‘상황의 명료성 확보에 도움이 됩니다’ 같은 표현은 어떤 정보를 남길지 직접 말하도록 편집했다. 생활 글의 ‘공간 활용의 효율성’도 ‘무엇을 남길지는 둘이 정해야 했다’처럼 그 장면의 행동으로 풀었다. 전문 보고서의 `conversion difference`는 구매·가입 전환처럼 읽힐 수 있어, 실제로 측정한 버튼 선택 행동을 설명했다. 낯선 표현을 풀다가 문장이 길어지면 문장을 나누도록 했다.

**요청과 설명을 자연스럽게 연결한다.** 한국어 슬랙에서 ‘확인이 필요해서 다시 확인한다’는 설명을 반복하지 않도록 줄였다. 검토 마감과 디자인팀 전달 시각은 담당자와 함께 나눠 적었다. 영어 보고서에서는 바로 앞 문장을 추상적인 말로 다시 요약하는 마지막 문장을 덜어냈다.

**매끄러운 문장과 정확한 이해를 별도로 확인한다.** 첫 평가에서 luna는 한국어 슬랙의 검토 마감인 오후 3시를 전달 시각처럼 설명했다. 실제 전달은 오후 4시다. terra는 영어 인계 문서의 검토 시각을 책임 종료 기한처럼 요약했고, 영어 슬랙에서는 승인 부재와 작업을 마칠 수 없는 상황의 알림 조건을 섞었다. 보완 평가에서는 세 모델이 해당 구분을 올바르게 답했다. 인계 검토를 연습 완료 상태와 섞어 표현한 첫 평가 답변도 있었으나, 다른 두 독자의 설명과 원문에서는 구분이 명확해 문서에 새 규칙을 추가하지 않았다.

이를 바탕으로 SKILL.md와 eval.md에 익숙한 표현을 고르는 기준, 전문 용어 대신 실제 행동을 가리키는 기준, 행동·담당자·시각의 연결, 편집본에서 의미를 다시 설명해 보는 점검을 보강했다. 영어·한국어 참고 지침에도 각각 어휘와 요청 문장의 예를 보탰다.

## 원문 정보가 부족해서 남긴 두 사례

**영어 인계 문서:** 자료 보완이 덜 끝나도 인계 준비 완료로 볼 수 있는지, 19일 재검토 뒤 실제 인계 시각을 어떻게 정하는지가 없다. 기존 담당자가 계속 요청을 처리한다는 규칙은 보존했지만, 편집자가 새 인계 규칙을 만들어 넣지는 않았다.

**영어 슬랙 요청:** ‘Approved 또는 수정 의견’으로 회신하라고 하면서, 승인 없으면 대체 이름을 쓴다고 되어 있다. 수정 의견만 도착했을 때도 승인으로 보는지는 정하지 않았다. 이 역시 문체 수정으로 대신 결정하지 않았다.

따라서 12편 중 10편은 중대한 편집 문제를 찾지 못했고, 두 편은 문장은 읽히지만 실제 업무에 사용하기 전에 작성자의 결정이 더 필요하다. 높은 점수로 이 두 문제를 덮지 않았다. 자세한 질문은 [편집 메모](editorial-notes.json)에 남겼다.

## 평가 의견을 전부 반영하지 않은 이유

마지막 영어 보고서 평가는 luna 86, terra 96, sol 100으로 갈렸다. luna는 후속 조사가 제안인지 더 밝혀 달라고 했지만, 본문에는 `We propose`와 `should check`가 있고 자신의 이해 답변에서도 제안 단계라고 정확히 설명했다. 같은 뜻을 반복해서 추가하지 않았다. terra는 `Based on both`의 지시 대상을 더 명시할 수 있다고 봤다. 직전 문장에 행동 결과와 참가자 의견이 함께 제시되어 있고 핵심 이해에 오류가 없어 선택 가능한 문체 개선으로 남겼다.

이 결과는 점수만 높이려고 고치면 오히려 설명이 반복될 수 있음을 보여 준다. 받아들인 지적은 실제로 무거운 어휘, 중복 문장, 혼동된 조건이었고, 사실상 해결되어 있거나 새 결정을 요구하는 지적은 구분했다.

## 의미 보존과 한계

완전한 원문과 최종본을 비교한 독립 검토에서 12편 모두 중대한 누락·추가·조건 변경을 발견하지 못했다. 별도 기계 점검에서도 명시된 보호 문자열, 인용문과 코드 표기, 숫자 토큰 집합이 유지됐다. 숫자 집합이 같다는 것만으로 의미 보존이 증명되지는 않으므로 사람·동작·시점·예외도 함께 읽었다.

보강한 스킬은 별도 편집자가 네 재검토 사례와 두 새 사례에 적용했다. 첫 독립 편집에는 여전히 무거운 문장과 반복이 일부 남아, 실제 출력에 근거해 세 사례를 추가 정리했다. 따라서 스킬만 넣으면 한 번에 항상 최선의 글이 나온다고 주장하지 않는다.

이 검증은 생성한 글과 모델 독자를 사용했다. 실제 독자 연구, 통계적으로 검증한 품질 점수, AI 작성 여부 판별이 아니다. 원문보다 얼마나 좋아졌는지의 수치 비교 실험도 아니다. 다만 여러 글 종류에서 구체적인 읽기 문제를 찾아 고치고, 의미와 개인적인 목소리를 보존하는지 확인한 사례로 사용할 수 있다.
