# Label study: findings and proposed next step

This small study examined how people interpret two labels in the Cedar scheduling prototype to help us make a near-term product decision. We saw differences in how participants used the labels, but their comments did not all point in the same direction. Based on both, we recommend using "Save for later" in the next prototype and keeping "Submit request" for the action that sends a request to an approver.

We tested two labels for the action that stores an unfinished request without sending it. Version A called it "Save draft"; Version B called it "Save for later". The rest of the screen, including the button placement and explanatory text, was identical. The prototype did not send real requests. We wanted to see whether participants could save their work and whether they understood that an approver would not yet receive anything. These are related questions, but succeeding at one does not necessarily mean succeeding at the other.

Twelve people participated in moderated sessions on 14 and 15 September 2026. All arranged shifts at least once a month, and none had used Cedar before. Six saw Version A first and six saw Version B first. Each person completed one unfinished-request task in each version, using different names and dates. This balanced the order, but the first task may still have taught people how the second task worked. That limits what we can conclude from the comparison.

On first exposure, five of the six participants who saw Version B chose the intended action without a moderator prompt. Three of the six who saw Version A did so. These are very small groups. The counts do not reliably predict how often future users would choose the intended action with each label. Across both exposures, nine participants correctly explained that saving would not notify an approver in Version B; seven did so in Version A. We assessed understanding from their explanations, rather than treating the button click itself as proof. One participant selected the intended action in both versions but still believed a manager would be alerted.

The comments help explain these results. Four participants associated "draft" with email and understood it immediately. Three others described it as a technical term or said they did not usually see it in scheduling tools. "Save for later" felt more familiar to several people, but two asked whether it meant the system would submit the request automatically later. Although more participants chose the intended action with this label, the surrounding copy needs to address that possible misunderstanding.

We propose using "Save for later" with the sentence "Only you can see this until you submit it." underneath the saved-request confirmation. This is a prototype decision, not approval to release the wording to every customer. We will retain "Submit request" as the separate sending action and will not add an automatic submission feature. A second round with eight new participants should check the automatic-submission misunderstanding explicitly before the release review on 6 October 2026.

The findings have other limits. Sessions were conducted in English on desktop screens. We did not test translated labels, mobile layouts, or people using screen readers. The prototype also omitted the pressure of an actual shift deadline. Product leads can use these findings to choose the next version to test, but should avoid reporting that the study proved an overall usability improvement.
