# 파일을 맡긴 뒤에 일어나는 일

우리 서비스의 업로드 대기열인 모래함은 사용자가 파일을 고른 순간부터 서버가 보관을 확인하는 시점까지의 과정을 담당합니다. 처음 접하면 상태가 여러 개라서 복잡하게 느껴질 수 있는데, 이것은 업로드라는 하나의 경험 안에도 서로 다른 종류의 기다림이 존재하기 때문이라고 볼 수 있습니다. 이 글에서는 화면 장식이나 압축 방식보다 대기열이 다음 작업을 고르는 기준에 우선적으로 초점을 맞추려고 합니다.

사용자가 추가한 파일은 먼저 `waiting` 상태로 들어갑니다. 한 계정에는 기다리는 파일과 전송 중인 파일을 합쳐 최대 20개까지 둘 수 있고, 파일 하나의 크기 제한은 50 MiB입니다. 여기서 1 MiB는 1,048,576바이트입니다. 20개가 이미 있으면 새 파일은 대기열에 들어가지 않으며 화면에 "대기열이 가득 찼습니다"가 표시됩니다. 실패해서 멈춘 파일과 완료된 파일은 이 20개에 포함하지 않습니다. 크기를 초과한 파일도 등록 전에 거절하므로 시도 횟수가 생기지 않습니다.

실제 전송을 담당하는 실행기는 계정마다 최대 2개입니다. 자리가 비면 등록 시간이 빠른 파일부터 가져가며, 등록 시간이 같으면 증가하는 등록 번호가 작은 파일을 먼저 고릅니다. 전송을 시작한 상태의 이름은 `sending`입니다. 따라서 세 번째 파일의 진행률이 한동안 0으로 보이는 것만으로 오류라고 판단할 수는 없습니다. 앞의 두 파일이 전송 중일 수도 있기 때문입니다. 이 설명은 모래함의 규칙이고, 다른 업로드 제품도 같은 방식으로 동작한다는 뜻은 아닙니다.

재시도는 조금 더 세부적인 판단을 필요로 합니다. 응답을 받지 못한 채 전송 시작 후 30초가 지나거나 HTTP 503을 받으면 자동 재시도 대상입니다. HTTP 400, 401, 403 및 나머지 응답 코드는 자동 재시도하지 않고 `failed`로 끝냅니다. HTTP 201만 성공 응답이며, 그때만 `done`으로 바뀝니다. 한 파일은 최초 전송을 포함해 최대 3번 시도합니다. 첫 번째 실패 뒤에는 2초, 두 번째 실패 뒤에는 6초를 기다립니다. 세 번째 시도가 실패하면 더 기다리지 않습니다. 이때의 기다림은 해당 파일에만 적용되며 다른 파일의 출발을 막지 않습니다.

재시도를 기다리는 상태는 `retry_wait`입니다. 이 상태도 대기열의 20개 한도에는 포함하지만 실행기 자리는 차지하지 않습니다. 시간이 지나면 다시 `waiting`으로 돌아가고, 원래 등록 시간과 등록 번호를 유지합니다. 그래서 재시도 파일이 새 파일보다 먼저 출발할 수 있습니다. 다만 진행 중인 전송을 밀어내지는 않습니다. 2초 또는 6초가 지났다는 말은 곧바로 전송을 시작한다는 보장이 아니라 다시 선택될 자격을 얻었다는 의미입니다. 실행기 두 개가 바쁘면 더 기다릴 수 있습니다.

여기까지 읽으면 실패한 요청을 또 보내서 파일이 두 개 생기는지 궁금할 수 있습니다. 각 파일에는 등록할 때 `upload_key`가 하나 만들어지고, 자동 재시도에서도 이 값을 그대로 보냅니다. 서버는 같은 키의 저장 결과를 24시간 보관합니다. 이미 저장을 끝낸 키로 요청이 오면 새 복사본을 만들지 않고 같은 파일 번호와 HTTP 201을 돌려줍니다. 이는 서버의 저장 성공과 브라우저의 응답 수신이 서로 다른 사건이기 때문에 필요한 중복 방지 장치입니다. 예를 들어 응답만 유실됐다면 두 번째 요청으로 첫 번째 저장 결과를 알 수 있습니다. 그렇다고 모든 통신 실패가 응답 유실 때문이라고 추정해서는 안 됩니다.

사용자가 취소하면 해당 파일은 `cancelled`가 되고 이후 자동 재시도는 없습니다. 이미 서버에 저장된 파일을 지우는 기능까지 포함하지는 않으므로, 전송 중 취소와 서버 파일 삭제는 별도 동작입니다. 또 브라우저를 새로 고치면 이 대기열은 복구되지 않습니다. 여기서 다루는 버전은 메모리에만 목록을 보관합니다. 새로 고친 뒤 같은 파일을 다시 등록하면 새 키가 생기므로 기존 파일과의 중복 방지도 보장되지 않습니다.

문제를 조사할 때는 파일명만 적는 것보다 등록 번호, 상태, 시도 횟수, 마지막 응답 코드를 함께 남기는 쪽이 상황의 명료성 확보에 도움이 됩니다. 특히 "세 번 재시도했다"라고 쓰면 최초 전송을 제외한 세 번처럼 읽힐 여지가 있습니다. 모래함 기록에서는 "총 3회 시도"라고 적어 주세요. 결국 먼저 확인할 것은 현재 상태와 총 시도 횟수이고, 기다리는 이유는 그다음에 연결해서 보는 편이 이해하기 쉽습니다.
